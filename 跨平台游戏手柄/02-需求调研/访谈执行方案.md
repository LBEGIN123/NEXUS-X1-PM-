# 深度访谈执行方案

版本：v1
更新日期：2026-09-22

输入：`02-需求调研/访谈提纲.md`、`调研计划.md`、`投放执行方案.md`、`分析口径与决策阈值.md`

> 本项目为模拟项目。本文件定义访谈执行方法，不含未采集的访谈数据。

## 1. 结论

1. **问卷投完就没有访谈招募池了，必须先补一道题。** 现有 `问卷.md`（v2）末尾没有征询受访者是否愿意接受后续访谈。问卷一旦投放，愿意深访的人就无从识别。**建议在预测试前补上这一题。**
2. **访谈对象优先从问卷回收样本里挑，不要另起招募。** 问卷已经采集了设备结构、切换频率和八项痛点打分，可以直接定向挑「换平台痛点打 4–5 分」或「设备组合特殊」的人深入问，成本远低于从零招募。
3. **深访要回答的是「为什么」，不是「多少」。** 问卷已经给出了比例，访谈的任务是解释这些比例背后的真实场景。
4. **D 组（流失用户）是访谈的重点。** 预测数据显示该组的怀疑点是品控 24.0%、续航 24.0%，价格只占 8.0%，问卷无法解释这个群体为什么不再信任第三方手柄。
5. **访谈不能出现产品卖点与价格。** 与问卷同理，一旦提前介绍产品，受访者的表述会被引导。

## 2. 需要先补的问卷题目

在 `问卷.md` 的 G 部分之后补一题：

> **G5. 我们后续可能邀请部分受访者做一次 30 分钟的语音访谈，会有感谢费。你愿意参加吗？**
> 愿意，请留联系方式 / 不愿意

这一题的作用是建立访谈招募池。没有它，第 3 节的定向挑选无法执行。

## 3. 访谈对象与配额

共 12–15 人，按四个样本组分配：

| 组别 | 人数 | 挑选条件 |
| --- | --- | --- |
| A 主机为主 | 4 | 换平台痛点任一项打 4 分以上 |
| B PC 为主 | 4 | 同上 |
| C 移动+多平台 | 4 | 切换频率为「每天多次」或「每天」，且 D1b 选「一键切换」 |
| D 流失用户 | 3 | 买过第三方手柄后退役或退货 |

挑选顺序：先满足 D 组（最难找），再按 A、B、C 补足。

若某组在问卷回收里找不到符合条件的人，记录缺口，不降低标准凑数。

## 4. 排期

与 `投放执行方案.md` 第 3 节的四周节奏对齐：

| 时间 | 动作 |
| --- | --- |
| 第 1 周末 | 从已回收样本中锁定首批访谈对象并发出邀请 |
| 第 2–3 周 | 完成 12–15 场访谈 |
| 第 4 周 | 编码、归纳，回填需求清单与证据台账 |

访谈与问卷回收并行，不等问卷全部结束再开始，否则排期会溢出。

## 5. 执行要点

| 事项 | 要求 |
| --- | --- |
| 开场 | 说明目的、时长、录音授权与匿名处理，先取得同意 |
| 顺序 | 先让受访者讲最近一次真实经历，再问评价。先讲结论会让细节丢失 |
| 提问方式 | 追问具体行为与时间，不接受「还行」「差不多」这类回答 |
| 产品介绍 | 全程不介绍产品功能、卖点与价格 |
| 概念环节 | 如需展示概念描述，使用 `问卷.md` D1 的同一段文字，不得加强 |
| 录音 | 取得同意后录音，逐字整理关键段落 |
| 时长 | 每场 30–40 分钟 |

访谈提纲见 `访谈提纲.md`，本文件不重复题目内容。

## 6. 记录与编码

每场访谈使用 `访谈记录模板.md`，产出后按以下规则编码：

| 编码对象 | 编码方式 |
| --- | --- |
| 关键原话 | 必须逐字摘录，不做概括改写 |
| 场景 | 归入需求清单的「用户场景」字段 |
| 痛点 | 与问卷 C4 的八项对应，无法对应的新建条目 |
| 现有替代方案 | 单独归类，用于判断差异化是否真实存在 |
| 优先级判断 | 只记录受访者自己的排序，不记录访谈者的判断 |

访谈无法产生统计结论，编码结果只用于解释问卷数据和补充场景，不得当比例使用。
