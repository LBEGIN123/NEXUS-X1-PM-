# 跨平台游戏手柄产品方案

面向 PC、Android、iOS、Switch、PS5、Xbox 的多平台游戏手柄，核心是一个动作：**按一下换平台，不需要重新配对**。

当前阶段：竞品分析已完成，需求调研已完成预测版，产品方案 v1 已冻结，上市路径已规划。
上市目标：2027 Q3，国内首发。

> 本项目为模拟项目。需求侧数据为程序生成的预测数据，不是真实调研结果。凡标 `PE` 的为预测证据，标 `E` 的为实证证据，两者严格分开编号。

## 四、证据规则

1. 外部事实必须带来源编号，来源清单放在各文档末尾。
2. 实证证据用 `E` 系列，统一在 `02-需求调研/证据台账.csv` 管理。
3. 预测证据用 `PE` 系列，见 `调研分析-预测版.md` 第 13 节，**不得与 E 系列混用**。
4. 拿不到的数据写「未获取」，不用行业印象或估算填充。
5. 事实、推断、假设分开写。
6. 价格、销量、评分这类易变字段必须带采集日期。

## 五、在 Codex 里怎么用

| 阶段 | 建议用法 | 为什么 |
| --- | --- | --- |
| 项目启动 | 单个任务，让 Codex 反问 | 简报没定清楚，后面全是返工 |
| 竞品扫描 | 联网搜索加并行子任务 | 多款竞品同时查，主对话只收结论 |
| 用户评价挖掘 | 并行子任务加结构化输出 | 大量评论分给多个任务读，回传带编号的证据 |
| 需求归纳 | 单个任务连续做 | 聚类和取舍需要上下文，不能并行 |
| 产品方案 | 单个任务，保持同一条线索 | 方案要反复推翻重来 |
| 上市后监控 | 定时任务 | 价格、评分、差评关键词持续跟踪 |

三条纪律：

- 一个阶段一个任务，跨阶段的长对话会让早期噪音干扰后面的判断。
- 结论必须落盘到文件，只在对话里说过的结论，下次任务读不到。
- 关键结论要求给出证据编号，没有编号的结论默认不可信。
