# 提示词：需求归纳

证据齐了之后，开一个任务做归纳：

```text
读 AGENTS.md、02-需求调研/证据台账.csv、02-需求调研/访谈提纲.md 对应的访谈记录。

任务：把证据归纳成需求，写进 02-需求调研/需求清单.csv。

规则：
1. 一个需求一行，需求描述必须是可验收的行为或指标，不能写「手感好」这类词。
2. 每个需求至少挂 1 条证据编号；只有 1 条证据支撑的需求，在备注里写「证据不足」。
3. 痛点强度按证据数量和质量打分，不要凭直觉排序。
4. 单独输出一节「被证伪的假设」：原先认为重要、但证据显示用户并不在意的功能。
5. 单独输出一节「证据冲突」：不同来源结论矛盾的，列出来不要强行统一。

最后按 P0 / P1 / P2 排优先级，并说明 P0 的入选理由。
```

第 4、5 条最重要。多数竞品分析失败在只收集支持自己观点的证据。
