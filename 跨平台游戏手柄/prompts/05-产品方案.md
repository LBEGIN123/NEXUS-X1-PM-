# 提示词：产品方案

用 Goal 模式（输入 `/goal`）开这个任务：

```text
目标：产出可评审的跨平台游戏手柄产品方案，写入 03-产品方案/PRD.md 和 产品定义.md。

约束：
- 目标零售价与 BOM 上限以 00-项目简报/项目简报.md 为准。
- 每个 P0 功能必须能追溯到 02-需求调研/需求清单.csv 里的需求编号。
- 硬件规格必须给出目标值、上下限和验证方式。
- 每个关键取舍必须能回答「为什么不选另一个方案」，并写进 04-决策记录/决策日志.md。

验收标准：
- 竞品对比表里，我们的每个差异化点都有对应竞品做不到的证据。
- 没有任何规格写成无法验收的形容词。
- 风险表里至少覆盖认证周期、BOM 超标、良率三个方向。

写完后自己检查一遍：随机挑 3 个结论，回头找它的证据编号，找不到就删掉或标注为假设。
```

「自己回头找证据」这一条是这套流程里最有价值的一步，能拦掉大部分编造出来的结论。
